# Progressive Writing

Treat the target artifact as an evolving manuscript: the durable working state
in which the document becomes complete, part by part. It is not a scratchpad
for disposable notes, rough alternatives, process commentary, or deferred
thinking. Each change should leave the manuscript more complete and usable
than before.

Before the first part and whenever the manuscript materially changes, read
`references/writing-quality-north-star.md`, resolving that path relative to
this `SKILL.md`. It is the common quality contract for Planner, Writer, and
Reviewer; it is not a source of requirements or authoring permission.

## Working state

Read the requirements, schema, and existing manuscript before writing. For a
review-directed revision, also read the current `review.md` and correct its
open findings without treating them as new requirements or schema authority.
The schema's ordered parts are the normal units of progress. Work only on a
part whose status is `Ready`; a `Blocked` part returns to the orchestrator.

For each part, inspect every applicable reference directly before relying on
it. The schema tells the part what to accomplish; it is not evidence for facts
about the referenced material. Establish the source's relevant structure and
read the necessary sections. If the available representation is only a
snippet, metadata, page description, related-content card, generated synopsis,
or visibly selective extraction, continue inspecting the underlying reference.
Do not fill an inaccessible or incomplete source with assumptions.

A consequential source claim must be traceable to a specific passage, table,
figure, or other substantive source location. Do not commit a number,
quotation, attribution, named finding, or strong conclusion that appears only
in a generated overview, even when the overview was returned while fetching
the source. Leave the affected work unresolved when that location cannot be
established.

## The part loop

For each part:

1. Establish its communicative job, requirements served, and authority from
   the schema.
2. Gather only the directly inspected source material or permitted knowledge
   needed for that job. Verify consequential numbers, quotations, attribution,
   scope, and qualifications at the source. Read the completed document and
   upcoming parts so the current part does not repeat prior material or consume
   a later part's primary content.
3. Write or revise that part in the evolving manuscript, using the form that
   best realizes its job. Keep completed material intact unless the current
   part genuinely requires an integration change.
4. Check the realized part against the four North Star dimensions:
   fidelity, attention economy, coherence, and craft. Fix a material problem
   before moving on.

Each loop iteration crosses a durable persistence boundary. Write the first
realized part to a new manuscript, then persist every later part as a separate
edit. Never hold several completed parts in memory and save them together: the
next part begins only after the current part exists in the target artifact and
has passed its check.

After all ready parts are realized, make one document-level pass for continuity
across part boundaries, repeated content, stable terminology, and the complete
authority boundary. This is integration, not permission to redesign the schema
or add unplanned content.

## Progressive boundaries

- Do not draft every part in a single response or treat the schema as a prompt
  for wholesale generation.
- Do not write process notes, checks, self-review commentary, or discarded
  alternatives into the manuscript.
- Do not make a quality improvement by losing required fidelity.
- Do not use the North Star to override requirements or authority.
